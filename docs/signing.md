# Постоянная подпись Android-релизов

Workflow DisputeAI уже умеет собирать стабильные APK с постоянным release-ключом.

Для включения постоянной подписи один раз создайте собственный keystore и добавьте в GitHub Actions четыре repository secret:

- `ANDROID_KEYSTORE_BASE64` — keystore целиком в Base64;
- `ANDROID_KEYSTORE_PASSWORD` — пароль keystore;
- `ANDROID_KEY_ALIAS` — alias ключа;
- `ANDROID_KEY_PASSWORD` — пароль ключа.

Во время релизной сборки workflow временно восстанавливает keystore в runner, передаёт параметры Gradle через переменные окружения и собирает `assembleRelease`. Сам keystore и пароли в репозиторий не записываются.

Если эти secrets ещё не настроены, CI продолжит работать и сможет выпустить APK прежним способом. После настройки secrets все последующие стабильные версии будут подписываться одним и тем же ключом и смогут обновлять друг друга поверх установленной версии.

Важно: release-keystore необходимо хранить отдельно в надёжном месте. Потеря ключа лишит возможности выпускать обновления с той же подписью.
