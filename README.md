# DisputeAI

**DisputeAI** — Android-приложение, в котором несколько языковых моделей обсуждают один вопрос, спорят друг с другом, учитывают реплики пользователя, а отдельная модель формирует итоговый результат.

> Не просто «чат с двумя ботами», а управляемая дискуссия из 2+ моделей с независимыми настройками и отдельной моделью результата.

## Как это работает

1. Пользователь задаёт вопрос или прикладывает файл.
2. Две или больше настроенных моделей по очереди отвечают в рамках заданного количества циклов.
3. Каждая следующая модель видит предыдущие реплики и может соглашаться, спорить, уточнять и исправлять ошибки.
4. Дискуссию можно поставить на паузу, добавить свою реплику или вложение и продолжить.
5. После завершения появляется кнопка **«Результат»**. Отдельная модель результата анализирует дискуссию и выдаёт конечный продукт по исходной задаче: ответ, решение, текст, промпт, стих, план и т. п.

## Основные возможности

### Резиновая дискуссия

- по умолчанию — две модели-участника;
- можно добавлять дополнительные модели;
- минимум две модели в дискуссии;
- настраивается, какая модель отвечает первой;
- количество циклов задаётся в общих настройках;
- во время цикла доступны **пауза**, **продолжение** и **стоп**;
- пользовательская реплика во время паузы становится частью общей истории и учитывается всеми участниками.

### Отдельная модель результата

Модель результата не обязана участвовать в споре и оценивает дискуссию независимо.

Для неё можно отдельно настроить:

- API и ID модели;
- собственный системный промпт;
- температуру;
- таймаут;
- reasoning, если модель его поддерживает.

Можно передавать ей всю дискуссию либо только последние **N циклов**. Реплики пользователя при этом сохраняются в контексте.

Если модель результата не настроена, приложение подскажет, что её нужно добавить в настройках.

### Настройки каждой модели

У каждого участника свой профиль:

- отображаемое имя;
- тип API;
- Base URL;
- API-ключ;
- ID модели;
- системный промпт;
- температура — по умолчанию модели или вручную;
- таймаут ответа;
- параметры reasoning.

Раздел **«Размышление»** показывается только тогда, когда приложение определило поддержку reasoning выбранной моделью. По умолчанию reasoning выключен, если модель позволяет его отключать.

Поддерживаются OpenAI-совместимые API (включая OpenRouter), Anthropic и Gemini.

### Вложения без постоянной пересылки

Вложения хранятся локально в рамках чата.

Модели получают только сведения о доступных файлах — имя, тип и внутренний ID. Само содержимое **не отправляется при каждом запросе**. Если модели действительно нужен файл, она запрашивает конкретное вложение, и приложение передаёт его только для необходимого вызова.

Поддержка конкретного типа файла зависит от выбранной модели и API. Текстовые файлы и изображения обрабатываются напрямую; документы вроде PDF передаются провайдеру как файл, если его API это поддерживает.

### История чатов

Боковая панель открывается кнопкой `☰` или свайпом от левой части экрана.

В ней находятся:

- **Новый чат**;
- поиск по названию и содержимому чатов;
- история разговоров;
- закрепление важных чатов;
- переименование и удаление;
- переход в настройки.

Название **DisputeAI** и поиск расположены в одной верхней строке панели. На основном экране лишней шапки с названием приложения нет.

### Нативный Android-интерфейс

Начиная с версии **1.1.0**, интерфейс полностью переписан на **Kotlin + Jetpack Compose**.

Старый WebView/HTML/JavaScript-интерфейс удалён. Поле ввода корректно учитывает системную клавиатуру, а `+`, отправка, пауза/продолжение и стоп встроены в единый нижний блок.

## Безопасность

- API-ключи шифруются AES/GCM;
- мастер-ключ создаётся и хранится в **Android Keystore**;
- API-ключи не сохраняются в истории чатов;
- резервное копирование приватных данных приложения отключено;
- перенаправления API-запросов блокируются;
- для внешних API требуется HTTPS;
- незашифрованный HTTP допускается только для локальной разработки без API-ключа;
- debug-сборка приложения не включает WebView-debugging, так как WebView больше не используется.

## Ограничение длины ответа

Для OpenAI-совместимых API DisputeAI не задаёт искусственный пользовательский лимит `max_tokens`. Если провайдер завершает ответ из-за собственного лимита длины, приложение может автоматически запросить продолжение и объединить части ответа.

Фактический предел всё равно определяется выбранной моделью и провайдером.

## Требования

- Android 7.0+ (`minSdk 24`);
- доступ к API хотя бы двух моделей для дискуссии;
- третья модель рекомендуется для независимого результата.

## Установка

Готовый APK публикуется в разделе **Releases** этого репозитория.

При установке APK не из магазина Android может попросить разрешить установку приложений из выбранного источника.

## Сборка из исходников

Проект использует Android Gradle Plugin, Kotlin и Jetpack Compose.

```bash
gradle :app:assembleDebug
```

Готовый APK появится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

GitHub Actions автоматически проверяет сборку проекта и сохраняет APK как артефакт CI.
