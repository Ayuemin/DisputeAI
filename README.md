# DisputeAI

**DisputeAI** — нативное Android-приложение, в котором несколько языковых моделей независимо предлагают решения, затем обсуждают и критикуют их, а отдельная модель формирует итоговый результат.

> Это не просто чат с несколькими ботами: первый цикл намеренно независимый, последующие циклы — общая дискуссия, а модель результата оценивает спор отдельно.

## Как работает дискуссия

1. Пользователь задаёт вопрос и при необходимости добавляет файлы.
2. В **первом цикле** все модели-участники отвечают независимо: каждая видит задачу пользователя, но не видит ответы других моделей этого же первого цикла.
3. Со **второго цикла** начинается взаимная критика: модели видят завершённые предыдущие ответы, ищут ошибки, дополняют друг друга и улучшают решение.
4. Модели могут сообщать, что им больше нечего добавить. Первый такой сигнал ещё не исключает модель: в следующем цикле она читает свежие реплики и либо возвращается в спор, либо подтверждает завершение. Служебные маркеры пользователю не показываются.
5. Когда остаётся одна активная модель, она получает последний содержательный ход, после чего дискуссия завершается.
6. Пользователь может вмешаться в спор: поставить его на паузу, добавить реплику или вложение и продолжить. После новой реплики модели снова считаются активными.
7. После завершения появляется кнопка **«Результат»**. Отдельная модель результата формирует конечный ответ по исходной задаче.

Заданное число циклов — это **максимальный предел**, а не обязательное количество. По умолчанию максимум — **10 циклов**, но спор может завершиться раньше.

## Модели и API

По умолчанию создаются две модели-участника. Можно добавлять дополнительные модели; для дискуссии должно оставаться минимум две.

Для каждой модели отдельно настраиваются:

- название;
- тип API;
- Base URL;
- API-ключ;
- ID модели;
- персональный системный промпт;
- температура;
- таймаут;
- reasoning;
- цвет сообщений;
- интернет-поиск через OpenRouter, если используется OpenRouter.

Поддерживаются OpenAI-совместимые API, Anthropic и Gemini.

### Reasoning

DisputeAI определяет возможности модели и показывает настройки reasoning только там, где они уместны. Учитываются и модели, у которых reasoning обязателен. Ошибки провайдера переводятся в более понятный пользователю вид.

### Интернет-поиск OpenRouter

Для каждой OpenRouter-модели поиск включается отдельно. Доступны движки:

- Auto;
- Native;
- Parallel;
- Perplexity;
- Exa.

Лимит поисковых вызовов задаётся отдельно, по умолчанию — **2 на один ответ**. Для режима Auto предусмотрена обработка временных ошибок поискового backend и fallback. Служебный JSON ошибок пользователю не показывается.

## Отдельная модель результата

Модель результата не участвует в голосовании и не обязана соглашаться с большинством. Её задача — сопоставить независимые варианты первого цикла, последующую критику и новые указания пользователя и выдать лучший конечный продукт.

По умолчанию включено **«Использовать всю дискуссию»**.

Также всегда доступен параметр **«Последних циклов для результата»**, по умолчанию **3**. Это значение сохраняется даже при включённой всей дискуссии и начинает применяться сразу после отключения режима «Использовать всю дискуссию».

Если используется ограниченный контекст, независимый первый цикл всё равно сохраняется отдельно, а к нему добавляются последние выбранные циклы и все реплики пользователя.

## Промпты

Редактируются отдельно:

- персональный промпт каждой модели;
- промпт первого независимого цикла;
- промпт последующих циклов;
- промпт модели результата.

Для промптов предусмотрен возврат к значениям по умолчанию.

## Streaming и Markdown

Ответы моделей отображаются по мере генерации. Поддерживаются Markdown, списки, форматирование и таблицы. Ответы разных моделей можно различать по индивидуальным цветам.

Длинное нажатие непосредственно по тексту ответа открывает действия:

- **Копировать ответ**;
- **Выделить текст**.

## Вложения

Файлы добавляются через `+` в поле ввода. Пока сообщение не отправлено, вложения показываются компактно как **«Вложения N»**. Нажатие раскрывает вертикальный список, где каждый файл можно удалить отдельно.

Вложения хранятся локально в рамках чата. Модели получают сведения о доступных файлах, а содержимое передаётся только тогда, когда оно действительно нужно выбранному API/модели, вместо постоянной повторной отправки на каждом ходе.

Поддержка конкретных форматов зависит от провайдера и выбранной модели.

## История чатов

Боковая панель содержит:

- новый чат;
- поиск по названию и содержимому;
- историю разговоров;
- закрепление;
- переименование;
- удаление;
- переход в настройки.

Панель открывается кнопкой `☰` или свайпом вправо. Зона начала этого жеста занимает **80% ширины экрана слева**, чтобы панель было проще вызвать на больших телефонах.

## Настройки

Экран настроек сгруппирован в разворачиваемые секции. Состояние секций сохраняется при обычных перерисовках интерфейса.

### Участники дискуссии

В одной секции находятся все модели-участники, добавление новой модели и модель результата. Шапка каждой модели кликабельна по всей площади, а не только по стрелке.

### Параметры дискуссии

Внутри находятся три отдельные разворачиваемые группы:

- **Циклы и порядок участников**;
- **Промпты циклов**;
- **Контекст результата**.

### О приложении

В нижней секции находятся:

- версия приложения;
- ссылка на репозиторий GitHub;
- информация о защите API-ключей;
- системные действия для оптимизации батареи и фоновой работы;
- сброс настроек.

## Работа в фоне

В «О приложении» доступны:

- запрос на исключение DisputeAI из оптимизации батареи;
- переход в системные настройки приложения для выбора разрешённого режима фоновой работы.

Конкретные названия системных режимов зависят от производителя устройства.

## Безопасность

- API-ключи шифруются AES/GCM;
- мастер-ключ создаётся и хранится в **Android Keystore**;
- API-ключи не записываются в историю чатов;
- резервное копирование приватных данных приложения отключено;
- перенаправления API-запросов не выполняются автоматически;
- для внешних API требуется HTTPS;
- незашифрованный HTTP допускается только для безопасного локального сценария разработки без API-ключа.

## Ограничение длины ответа

Для OpenAI-совместимых API DisputeAI не задаёт искусственный пользовательский лимит `max_tokens`. Если провайдер завершает ответ из-за собственного лимита длины, приложение может запросить продолжение и объединить части ответа.

Фактический предел всё равно определяется моделью и провайдером.

## Требования

- Android 7.0+ (`minSdk 24`);
- доступ к API минимум двух моделей для дискуссии;
- отдельная модель рекомендуется для независимого результата.

## Установка

Стабильный APK публикуется в разделе **Releases** этого репозитория.

При установке APK не из магазина Android может попросить разрешить установку приложений из выбранного источника.

## Сборка из исходников

Проект использует Kotlin, Jetpack Compose и Android Gradle Plugin.

```bash
gradle :app:assembleDebug
```

Готовый APK появится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

GitHub Actions автоматически проверяет сборку и сохраняет APK как артефакт CI.
